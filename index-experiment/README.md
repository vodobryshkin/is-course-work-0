# Простой эксперимент Goalissimo
## Что внутри

- `01_schema.sql`, `03_routines.sql` — таблицы, функции и триггеры.
- `02_fill.sql` — один фиксированный набор среднего размера для этого эксперимента:
  50 турниров, 1000 команд, 20000 игроков, 19000 матчей, 72000 событий.
- `04_hypopg.sql` — планы трёх запросов без индексов и с гипотетическими индексами.
- `05_explain.sql` — реальные планы с ANALYZE и BUFFERS.
- `bench/` — четыре запроса: расписание UC7, события UC11.1,
  статистика игрока UC11.3, статистика команд UC11.2/UC14.2.
- `final_indexes.sql` — три исследуемых индекса.
- `rollback_indexes.sql` — их удаление.
- `run.sh` — линейная последовательность команд, без автоматического подбора и построения отчётов.

## Результаты

- `results/hypopg.txt` — оценочная стоимость до/после гипотетических индексов.
- `results/before.txt`, `results/after.txt` — средняя задержка, TPS,
  ошибки и среднее время команд в каждом сценарии.
- `results/explain_before.txt`, `results/explain_after.txt` — реальные планы.
- `results/sizes.txt` — размер дополнительных индексов.

В before/after сравниваются одинаковые четыре сценария, четыре соединения,
пять секунд прогрева и тридцать секунд измерения. Данные между замерами не меняются.
PRIMARY KEY, UNIQUE и триггеры сохранены. Новый набор данных используется на всех этапах.
Статистика команд вызывается через твою get_team_statistics; HypoPG проверяет
три прямых SQL-запроса, поскольку обычный внешний EXPLAIN функции скрывает её внутренний план.

## Повторный запуск и остановка

Первый запуск предполагает пустую тестовую БД. Для повторного запуска
сначала удалитие только данные этого локального стенда, затем запусти заново:

```bash
docker compose down -v
bash run.sh
```

Чтобы просто остановить контейнер: `docker compose stop`.
Если произошла ошибка — пришли её текст и `results/load.txt`.
Для разбора результата достаточно `before.txt`, `after.txt` и `hypopg.txt`.
